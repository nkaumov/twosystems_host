# Правила разработки

## Общие
- Никаких больших файлов.
- Если компонент/контроллер/сервис разрастается, выноси подмодули по смыслу (`/controllers`, `/renderers`, `/shared`, `/model`, `/ui`).
- Не менять логику, если задача про тексты/локализацию/кодировку.

## Анти-mojibake (обязательно)
- Текстовые правки делать только точечно через `apply_patch`, без массовой перезаписи файла.
- Не копировать в код битые строки из терминального вывода.
- После правок текста проверять файл на маркеры поломанной кодировки: `Р...`, `С...`, `Ѓ`, `Ђ`, `�`.
- Перед завершением задачи проверять текстовые изменения через `git diff`.
- После текстовых правок запускать `npm run build` (для соответствующего приложения).
- Если затронут UI, дополнительно проверять ключевые строки: `title`, кнопки, `aria-label`, тексты ошибок.
- Для новых и редактируемых файлов использовать UTF-8.
